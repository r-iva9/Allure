# What is Allure?

Allure is an entire ecosystem, a container of modules and frameworks. <br>
Currently, it connects all of them with shared practices such as garbage collection, reactivity and state machinery.<br>
The features it contains focus on opportunities, they're low-level, which means it's very easy to extend and optimize.

## Why Allure?
- **🪄 *Freely extensible ecosystem***
    > Built so you can keep and use only whatever you need.

- **⚡ *Low Level originally***
    > Create __your own__ components and features!

- **🍀 *Enforces modern practices***
    > Introduces straightforward concepts.

- **⬆️ *Any level***
    > No matter your level, you __can__ begin working with Allure, gradually expanding your knowledge.

> [!IMPORTANT]
> <h2 style="border-top: none; margin-top: 0; padding-top: 0;">Allure is 0.1.0 software</h2>
> This means that Allure has unfinished documentation, overlooked issues and bugs.
> 
> Modding and utilizing Allure as a "meta-framework" over any UI framework is currently being worked on.<br>
> As of right now, you can use *5 preset frameworks/libraries* within the Allure container.

## What does Allure currently can contain?
All of these frameworks can be connected together!<br>
And you can remove anything you don't need.

- ### AllureUI: A fantastic UI framework
    > - *Garbage Collection:* Integrated into everything.
    > - *States:* The core to everything!
    > - *Amplified Tables:* The core to UI.

- ### AllureRx: Observable streams
    > - The same states, but with filters and operators.

- ### AllureBundle: An example of what you can make yourself!
    > - *Extensions: stack, computed, spring, effect, observer:* All made given state customization.
    > - *Shortcuts:* Clean your code.

- ### Aserde: Allure's ser/des module
    > - A schemaless serializer and deserializer with customizable types.

- ### AllureWorker: Thread communication interface
    > - Asynchronous workers let you communicate between threads with your own interface.

- ### And many more to come!
